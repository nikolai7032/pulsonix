Pulsonix 14 Corporate — исчерпывающий справочник

Личный справочник · объединяет общее руководство по Pulsonix 14 Corporate (на основе официальной документации 14.0 и Vault Users Guide 14.0) и разбор конкретных ситуаций из рабочей переписки по проекту переноса схемы OrCAD → Pulsonix. Названия команд — на английском, как в программе; описания — на русском.

1. Назначение и область применения

Pulsonix — система автоматизированного проектирования электроники (EDA) британской компании WestDev Ltd. В одной среде объединены ввод принципиальной схемы, моделирование (в версии 14 — встроенный симулятор PulsonixSim на базе ngspice), проектирование печатной платы, трёхмерный просмотр и выпуск производственных файлов.

Руководство описывает рабочий процесс от создания схемы до передачи файлов на производство и содержит справочники горячих клавиш и команд. Оно опирается на официальную документацию Pulsonix 14.0 (онлайн-справка и Users Guide, редакция от 05.01.2026).

1.1. Что понимается под Corporate Edition

Название «Corporate» само по себе не определяет набор функций: состав Pulsonix зависит от лицензии. Дополнительные (платные) возможности включают, в частности:

  • Pulsonix Vault — централизованное хранилище проектов и библиотек с ревизиями;
  • Database Connection (PDC) — подключение к корпоративной базе компонентов;
  • Network Licensing (NLS) — плавающие сетевые лицензии;
  • Advanced Router / Auto Place — автотрассировка и авторазмещение;
  • Interactive High Speed и Advanced Technology — дифференциальные пары, согласование длин, микропереходы, встроенные компоненты.
Как проверить состав своей лицензии

Откройте Help → License Information. Там перечислены модули, которые включены в Вашу лицензию. Команды, недоступные по лицензии, в меню будут неактивны.

2. Интерфейс и базовая навигация

2.1. Главное окно

Pulsonix работает в многодокументном режиме (MDI): одновременно можно открыть несколько схем, плат, библиотек и технологий. Меню расположены слева направо в порядке этапов проектирования. Основные элементы окна:

  • строка меню — её, как и панели инструментов, можно открепить и сделать плавающей;
  • панели инструментов — состав зависит от типа активного документа (Schematic или PCB) и настраивается в Tools → Customise;
  • рабочая область документа;
  • докируемые окна (браузеры) — см. п. 2.3;
  • строка состояния — подсказка о текущем действии, свойства выделенного объекта, координаты X/Y (Abs или Rel), текущая сетка и единицы.
Активная строка состояния

Двойной щелчок по полям строки состояния позволяет менять значения на месте: щелчок по Abs переключает абсолютные/относительные координаты, по Grid — открывает диалог сеток, по единицам — переключает мм ↔ thou. Если команда ведёт себя неожиданно, сначала прочитайте подсказку в строке состояния: там написано, чего ожидает программа.

Знаки + или − после координаты в строке состояния означают, что фактическое значение чуть больше или чуть меньше показанного (точность отображения ограничена настройкой Units).

2.2. Светлая и тёмная тема

Tools → Customise → вкладка Application Look → переключатель Dark → Apply Changes. По умолчанию после установки используется светлая тема.

2.3. Докируемые окна и браузеры

2.5. Способы выделения

  • Одиночный щелчок — выделяет один объект (возможно, часть целого, например один сегмент дорожки).
  • Ctrl + щелчок — добавляет объект к выделению или убирает его.
  • Shift + щелчок — расширяет выделение до целого объекта: вся дорожка цепи, весь компонент по площадке; повторный Shift расширяет дальше.
  • Ctrl + Shift — добавляет к выделению целые объекты.
  • Path Select — сегменты между двумя точками (удобно для локального сужения дорожки: Select Path, затем S).
  • Frame / Polygon / Line Select — выделение прямоугольником, произвольным многоугольником или линией (контекстное меню в пустом месте).
  • N (Select Next) — перебор объектов под курсором в плотных местах.
  • Latch Mode — инструмент (Move, Rotate, Mirror) «защёлкивается» и применяется к объектам по очереди; выход — Esc или кнопка Select.

3. Настройка среды и проекта

3.1. Папки (Setup → Folders)

Задают начальную папку программы и расположение библиотек, технологических файлов, профилей, цветовых файлов, макросов, скриптов, STEP- и SPICE-моделей, отчётов, CAM-выхода и резервных копий. В путях можно использовать переменные окружения, заключённые в символы % (например, %PROJECT%).

Корпоративная практика

Пути к общим библиотекам и технологиям должны указывать на согласованные сетевые папки (или Vault). Не копируйте корпоративные библиотеки локально без согласования — иначе появятся расходящиеся версии.

3.2. Единицы и сетки

  • Units (Shift+U) — единицы и точность; Ctrl+U — быстрое переключение мм ↔ thou.
  • Grids (Alt+G) — рабочая сетка (Working), сетки компонентов, текста, дорожек, переходных отверстий. G меняет шаг, Ctrl+G показывает/скрывает сетку, Shift+W — рабочая сетка, Shift+N — работа без сетки.
  • Relative Coords (Shift+R) — переключение на относительные координаты; Shift+X задаёт относительное начало, X показывает его.

3.3. Параметры (Tools → Options, клавиша O)

Пользовательские параметры сохраняются в реестре и действуют для всех проектов: интервал автосохранения, единицы по умолчанию, число уровней Undo, стиль курсора, чувствительность мыши, интерактивные режимы трассировки и перемещения, онлайн-проверки DRC/ERC, предупреждения. Параметры конкретного проекта задаются в Setup → Design Settings и сохраняются вместе с проектом.

3.4. Резервные копии

Настройте автосохранение и резервные копии в Options → Design Backups и папку резервных копий в Setup → Folders. Восстановление — File → Restore Backup. Перед крупными изменениями сохраняйте промежуточную ревизию вручную.

3.5. Перенос настроек на другой ПК

Установку нельзя просто скопировать — используйте установщик. Настройки интерфейса (панели, клавиши, параметры) переносятся через Save Configuration и Load Configuration.

4. Создание и ведение проекта

4.1. Порядок создания

  • File → New (Ctrl+N) → вкладка Designs → тип Schematic Design или PCB Design. На вкладке Technologies & Profiles создаются технологии и профили, на вкладке Wizards — мастера.
  • Выберите технологию (Technology File), утверждённую в организации. Для схемы — также профиль листа (рамка и штамп).
  • Сохраните проект (Ctrl+S) в согласованной папке. Рекомендуемое имя: <Изделие>_<Обозначение>_<Ревизия>.
  • Проверьте единицы, сетки и правила (Setup → Technology, клавиша T).
  • Перед крупными изменениями сохраняйте ревизию (Save Copy As) или фиксируйте её в Vault.

4.2. Связь схемы и платы

Схема и плата — отдельные файлы, связанные синхронизацией. Переключение между ними — команда Switch between Schematic and PCB. Изменения передаются в обе стороны через механизм синхронизации/ECO (см. главу 7).

5. Принципиальная схема (Schematic)

5.1. Подготовка

  • Создайте Schematic Design с корпоративной технологией и профилем листа.
  • Проверьте технологию схемы (T): стили линий и текста, правила ERC, типы выводов.
  • Убедитесь, что подключены нужные библиотеки (Library Manager) и, если используется, база данных PDC или Vault.

5.2. Размещение компонентов

  • Shift+C (Insert Component) или перетаскивание из Part Browser.
  • Найдите компонент по имени или атрибутам; при необходимости используйте маски * и ?.
  • Щелчком разместите символ. Во время перемещения: R — поворот, M — отражение, правая кнопка — дополнительные действия.
  • Многосекционные компоненты: неиспользованные вентили автоматически попадают в Component Bin (B), откуда их можно перетащить на лист.
  • Проверьте позиционное обозначение, номинал и атрибуты (I или Alt+Enter — свойства).

5.3. Соединения

  • Insert Connection — рисование связей; двойной щелчок по связи — её редактирование.
  • Net Labels — именование цепей; одноимённые цепи соединяются логически.
  • Signal References — символы питания и земли, глобальные сигналы.
  • Bus / Bus Reference — шины; Page Link и J (Jump To Page) — связи между листами.
  • Branch Point и Star Point — управление топологией цепей (например, единая точка соединения земель).
  • F2 (Change Net) — переназначение цепи.

5.4. Иерархия

Крупные схемы разбиваются на иерархические блоки: Insert Block Instance и Block Port; переход внутрь блока — PgDown, выход — PgUp. Готовый фрагмент можно превратить в блок командой Cut To Block.

5.5. Проверка ERC

  • Онлайн-проверка: Options → Online ERC (режимы: непрерывно, при отпускании объекта или после редактирования); её также можно переключать из контекстного меню во время Insert Connection.
  • Пакетная проверка: Tools → Electrical Rules Checking — проверяет всю схему, в том числе по дополнительным правилам, которых нет в онлайн-режиме.
  • Просмотрите ошибки в ERC Error Browser; E / Shift+E — следующая/предыдущая ошибка.
  • Проверьте аннотацию (Auto Rename), неподключённые выводы, конфликты типов выводов и одиночные метки цепей.

6.2. Создание нового элемента

  • Найдите элемент в утверждённых библиотеках (Find Parts / Find Footprints), чтобы не создать дубликат.
  • Создайте символ (Symbol Editor или Symbol Wizard).
  • Создайте посадочное место (Footprint Editor или Footprint Wizard) по данным производителя и правилам IPC, принятым в организации.
  • Свяжите их в Parts Editor (или Part Wizard): вентили, соответствие выводов (pin-to-pad), атрибуты.
  • Выполните Check Pin Mappings и сохраните элемент в библиотеку (Save To Library).
  • После изменения библиотек выполните Regenerate Part/Footprint Library Indexes.

6.3. Контрольный список проверки посадочного места

7. Передача схемы в PCB и синхронизация

Рекомендуемая схема работы: схема — главный документ (master). Плата создаётся из схемы, а все электрические изменения вносятся в схему и передаются в плату.

7.1. Перевод схемы в плату (Translate To PCB)

  • Устраните ошибки ERC и проверьте Component Bin: компоненты, оставшиеся в корзине схемы, не переводятся (кроме неиспользованных вентилей уже размещённых многосекционных компонентов).
  • В редакторе схем выберите Tools → Translate To PCB.
  • Укажите имя платы. Оставьте имя по умолчанию, совпадающее со схемой, — так проще работать с Synchronise Designs и Cross Probe.
  • Выберите Technology платы (слои, плоскости питания, стили площадок и дорожек) и, при необходимости, Profile (контур платы, оформление, предразмещённые компоненты, например разъёмы).
  • Отметьте Unplaced components to bin, чтобы компоненты попали в корзину; Show Bin откроет её автоматически. Без этой опции компоненты складываются стопкой в рабочей области или вокруг контура платы.

Особенности перевода: для каждого компонента берётся первое найденное по пути библиотек описание Part; документационные символы (Doc Symbols) не переводятся; скрытые выводы питания и земли подключаются автоматически по предопределённым именам цепей в описании Part.

7.2. Синхронизация (Synchronise Designs)

  • Команда доступна в схеме и в плате (меню Tools). Она сравнивает списки соединений и показывает отчёт о различиях; кнопка Update PCB вносит изменения в плату.
  • Изменения в списке соединений могут удалить уже проложенные дорожки — просмотрите отчёт перед обновлением.
  • Компоненты и выводы, существующие только в PCB, в сравнении не участвуют.

7.3. Обратная аннотация (Back Annotate)

Изменения аннотации, сделанные в плате (переименование, перестановка вентилей и выводов), передаются в схему через Back Annotate внутри Synchronise Designs. Делайте это до обновления платы: сравнение не учитывает ожидающую обратную аннотацию. Какие перестановки передавать, задаётся в Options → Synchronisation.

7.4. Защита платы и полный обратный ECO

  • PCB Safe Mode (Options → General) запрещает электрические изменения в плате — рекомендуется включать, чтобы правки шли только через схему.
  • Если главным документом нужно сделать плату: синхронизируйте проекты, затем в плате в Design Settings → Synchronise снимите PCB in Safe Mode и включите Allow Update of Schematic to match PCB.
  • File → Import ECO — только для внешних нетлистов и проектов других систем; для схем Pulsonix используется Synchronise Designs.
  • Cross Probe — подсветка соответствующих объектов в схеме и плате одновременно.
Важно

Если менять связи в плате вручную при включённой схеме-мастере, Synchronise Designs покажет различия, а Update PCB удалит Ваши изменения. Переносите такие правки в схему вручную.

8. Проектирование печатной платы

8.1. Технология и слои

Технология PCB (T) содержит стили площадок, дорожек и переходных отверстий, правила зазоров (Spacing Rules), DFM/DFT-правила, классы цепей, слои, классы слоёв, материалы и диапазоны слоёв (Layer Spans). Стек слоёв можно вывести на чертёж командой Insert Layer Stack Preview.

8.2. Контур платы

  • Insert Board — нарисуйте контур или загрузите профиль платы (Load PCB Profile).
  • Альтернатива — импорт контура из DXF, IDF или STEP.
  • Задайте начало координат платы (Insert Board Origin).
  • Добавьте крепёжные отверстия (Insert - Mounting Hole) и запретные зоны (Insert Area с Keep Out).

8.3. Размещение компонентов

  • Компоненты из Component Bin (B) перетаскиваются на плату; команда Tools → Place Around Board раскладывает их вокруг контура.
  • При наличии лицензии — Auto Place (обмен с Component Bin в обе стороны).
  • R / M — поворот и перенос на обратную сторону (для SMD площадки переносятся автоматически).
  • Группируйте по функциональным узлам, учитывайте тепловой режим, доступ к разъёмам и механические ограничения.
  • Shift+O / Shift+L — оптимизация воздушных связей после перемещений.

8.4. Трассировка

  • Убедитесь, что назначены классы цепей и правила зазоров, включите онлайн-DRC (\).
  • Двойной щелчок по воздушной связи превращает её в дорожку для ручной прокладки.
  • Начать дорожку: выбрать связь → правая кнопка → Edit, либо Insert → Insert Track, либо двойной щелчок по площадке.
  • Во время прокладки: щелчок — угол; Shift+щелчок — принудительный угол; двойной щелчок — Route to Finish (прямо до целевой площадки, при необходимости с автоматическим переходным).
  • L, Enter — смена слоя на парный со вставкой переходного; Ctrl+щелчок — то же одним действием (переводит на нижний слой, поэтому в многослойных платах удобнее L); V — завершить на переходном отверстии.
  • S, Enter — переключение на альтернативный стиль из Net Class (сужение дорожки, necking); Backspace — удалить последний сегмент.
  • Для точных значений используйте = (координата) и + (смещение).
  • Скругление/фаски углов — Mitre and Fillet Corner; каплевидные переходы — Tools → Teardrops; отводы от выводов — Tools → Create Breakout.
  • Заливки: Insert Template (область) → Utilities → Pour Copper (заливка с учётом правил).
  • При наличии лицензии — Auto Route / Advanced Router; дифференциальные пары и согласование длин — модуль High Speed.

9. Проверка проекта и выпуск производственных файлов

9.1. Проверки перед выпуском

  • Запустите Design Rules Check (меню Tools, панель PCB или контекстное меню DRC Error Browser). В диалоге отметьте группы проверок: Spacing (зазоры), On Grid (объекты на своих сетках; площадки проверяются по сетке дорожек), Keep In/Out, Manufacturing, Testpoints, Nets. Source — весь проект или только выделенное; Clear All Errors удаляет все старые маркеры.
  • Переходите по ошибкам клавишами E / Shift+E или двойным щелчком в DRC Error Browser; повторяйте проверку до чистого результата. Заблокированные (locked) ошибки при повторных проверках игнорируются, их сброс — Clear Locked Errors.
  • DRC учитывает варианты исполнения: зазоры между компонентами, которые никогда не устанавливаются вместе, не считаются ошибкой.
  • Убедитесь, что не осталось неразведённых связей и что схема синхронизирована с платой.
  • Проверьте контур, маски, шелкографию (Breaking Silkscreen), сверловку и технологические слои.
  • Проверьте 3D-коллизии (3D - Detect Clashes) и высоты компонентов.

12.1. Отчёт горячих клавиш

  • Запустите Pulsonix 14 и откройте любой проект.
  • Tools → Customise → вкладка Keyboard (в справке также называется Shortcut Keys).
  • В поле Category выберите All Commands.
  • В блоке Assignment Report нажмите By Command, затем By Key.
  • Сохраните оба отчёта (Ctrl+A, Ctrl+C → вставка в Блокнот или Word).

Альтернативный путь: Output → Reports → отчёт Shortcut Keys (By Name или By Function).

  • Tools → Customise → вкладка Commands → категория All Commands.
  • Описание выбранной команды отображается в поле Description.
  • Команды, доступные в текущем контексте, показывает Edit → Run Command.

13. Корпоративная конфигурация и общие ресурсы

13.1. Сетевое лицензирование (NLS)

Лицензии размещаются на сервере и выдаются клиентам по мере запуска программы; ключ USB или MAC-адрес привязывается к серверу. Управление — Pulsonix Network License Server Manager (журналы, отключение клиентов, рассылка сообщений). Установка описана в Network Licensing Installation Guide.

13.2. Pulsonix Vault

Хранилище на базе PostgreSQL для библиотек, проектов и производственных данных с ревизиями, перекрёстными ссылками и журналом аудита. Подробно — в главе 14.

13.3. Database Connection (PDC)

Связывает библиотеку Pulsonix с корпоративной базой компонентов: поиск и вставка через Database Bar, сверка и обновление атрибутов (Check and Update Against Database), учёт в отчётах Report Maker.

14. Работа с Pulsonix Vault

Vault — система управления данными Pulsonix. В простейшем виде это «управляемая библиотека», но в нём можно хранить также проекты и производственные файлы (Gerber, ODB++). Vault контролирует, кто и как изменяет данные, знает связи между элементами и хранит историю ревизий каждого элемента.

Нужен ли Vault

Vault — платная опция лицензии (проверяется в License Manager). Использовать его не обязательно: можно работать с обычными библиотеками и файлами. Одна галочка в Tools → Options скрывает все команды Vault из интерфейса. Если в фирме уже есть своя система документооборота, Vault обычно не нужен.

14.1. Устройство

  • Сервер — база данных PostgreSQL (в v14 — версия 14.5) хранит описание элементов, связи, пользователей и журнал.
  • Папка данных — сами файлы хранятся не в базе, а в общей сетевой папке с правами чтения и записи для всех пользователей Vault (путь в формате UNC: \\сервер\ресурс\папка).
  • Клиенты — Pulsonix на рабочих местах подключается к базе через ODBC-драйвер PostgreSQL (в v14 — версия 13.0), который ставится вместе с Pulsonix.
  • Для работы с Pulsonix 14 все три компонента должны быть актуальны: ODBC 13.0, PostgreSQL 14.5, база Vault версии 14.0.
Важно

Никогда не открывайте и не изменяйте файлы в папке данных Vault вручную через Проводник — это может безвозвратно повредить хранилище.

14.2. Что хранится в Vault

Вид данныхЭлементы
БиблиотечныеParts, Footprints, Schematic Symbols, Schematic и PCB Doc Symbols, 3D Packages, STEP-модели
ФайловыеСхемы и платы, технологии (SCM/PCB), профили, файлы блоков схем, панели PCB, прочие файлы (Generic Files)

Каждый элемент получает уникальный идентификатор IID (Item ID). При каждом сохранении в Vault создаётся новая версия (метка времени), которой присваивается имя ревизии по схеме нумерации. Сочетание IID и версии однозначно указывает конкретное состояние элемента — например, Part знает, какую именно версию посадочного места использует. У каждой установки свой Vault ID, поэтому элементы разных хранилищ не смешиваются: чужой элемент можно только занести к себе как новый.

Рекомендуемый подход: разработку вести в обычных локальных библиотеках, а в Vault помещать готовые, «опубликованные» элементы.

14.4. Подключение рабочего места

  • Запустите Pulsonix: Setup → Vault — откроется диалог Vault Setup, вкладка Sign In.
  • Введите имя пользователя и пароль, выданные администратором (у нового хранилища есть встроенный пользователь admin).
  • Укажите Server Name (компьютер с PostgreSQL) и Server Port (по умолчанию 5432). Проверьте поле ODBC Driver — обычно PostgreSQL ANSI(x64); при необходимости — кнопка Change или Default.
  • Нажмите Test. При успехе появится сообщение «Vault successfully connected», а в поле Data Folder — путь к папке данных.
  • На вкладке Options → Personal Settings задайте локальные папки (см. п. 14.5) и нажмите OK.

На вкладке Sign In есть два набора полей — Primary и Alternate Sign-in: удобно, если Вы работаете в двух ролях (например, разработчик и библиотекарь) и нужно быстро переключаться.

Безопасность

Встроенная учётная запись admin создаётся с паролем по умолчанию «password». Если на Вашем Vault он не сменён — сообщите администратору: иначе хранилище может изменить любой, кто знает пароль по умолчанию. Каждому сотруднику нужна своя учётная запись: по ней журнал аудита показывает, кто что менял.

В Setup → Folders → Libraries (или на вкладке Folders в Library Manager) появляется специальная строка [Vault]. Рекомендуемый порядок поиска:

  • папки Checked Out / Copied Out — выше [Vault], чтобы программа видела Ваши локальные правки первыми;
  • [Vault] — опубликованные данные;
  • остальные локальные библиотеки — ниже [Vault] (только то, что ещё в разработке).

14.6. Повседневная работа

  • Vault Manager (меню File или панель Vault) — главное окно: вкладки Browser, Libraries to Vault, Designs to Vault, Generic Files to Vault, Audit Trail.
  • Browser: слева дерево виртуальных папок, справа список элементов и нижняя таблица в одном из режимов — Audit Trail (история элемента), Where Used (где используется, например все Parts и проекты с данным footprint), Refers To (на что ссылается, например все компоненты проекта). Кнопки справа: Search, Move, Delete, Check Out, Copy Out, Uncheck, Reports.
  • Search — поиск по всему Vault: до трёх условий по полям для каждого типа элементов и по состоянию «взят на правку». Поиски можно сохранять в файлы и вызывать из выпадающего списка рядом с кнопкой.
  • В диалогах Insert Component, Library Manager, File → New, Insert Block Instance элементы Vault показываются как обычные библиотеки, но выделены цветом. В Library Manager элементы, взятые на правку, выделены отдельным цветом (по умолчанию розовым) — это «из Vault, но сейчас не в Vault».
  • Цвета настраиваются на вкладке Colours диалога Vault Setup, в том числе по значениям атрибутов (например, Status = Obsolete — красный фон).

Изменение библиотечного элемента

  • Найдите элемент в Library Manager или Vault Manager и выполните Check Out (или Check Out … And Edit из контекстного меню в проекте).
  • Отредактируйте элемент в соответствующем редакторе и сохраните.
  • Выполните Check In с комментарием.
  • Если элемент используется в Parts, появится диалог Update Cross References — подтвердите обновление ссылок, чтобы Parts начали использовать новую версию.
  • Чтобы обновить уже размещённые в проекте компоненты, выполните Utilities → Reload From Library и отметьте источник: Library, Vault или оба. Опция Only reload if different version перезагрузит только изменившиеся элементы.

Удаление

Удалять могут только пользователи с правом Delete для данного типа. Элемент, на который ссылаются другие (например, footprint в Part или проекте), удалить нельзя. Отдельную версию можно удалить правым щелчком по её строке в режиме Audit Trail.

14.7. Перенос данных в Vault (для ответственного за библиотеки)

Страницы Libraries to Vault и Designs to Vault окна Vault Manager. Сначала в Vault Setup → Options → Database Settings выбирается строгость ссылок (Referenced Items) — настройка действует для всех пользователей:

РежимСмыслКогда использовать

Linked using NameСсылки разрешаются по имени при Check In; для проектов дополнительно должна совпасть версия библиотечного элементаРекомендуемый вариант для переноса существующих библиотек без правки

  • Добавьте источники: Add All Libraries (весь путь поиска), Add Files, Add Current/Open Designs (можно извлечь элементы из старых проектов).
  • Оставьте включённой опцию Move Completed Libs to Backup.
  • Задайте папку назначения в Vault и комментарий для журнала.
  • Выберите тип данных (All Library Types — сначала символы и footprints, в конце Parts), нажмите Check и изучите отчёт.
  • Нажмите To Vault.
  • После переноса общих корпоративных библиотек каждый пользователь должен убрать их папки из пути поиска и работать через [Vault].

Ограничения: имена элементов одного типа в Vault должны быть уникальны; в именах папок нельзя использовать символы : / \ ? *.

14.8. Подключение не работает: проверка ODBC

  • Пуск → наберите ODBC → ODBC Data Sources (64-bit) (или Win+R → %WINDIR%\system32\odbcad64.exe).
  • Вкладка Drivers — должен быть PostgreSQL ANSI(x64). Pulsonix также понимает драйверы PostgreSQL ANSI и PostgreSQL ODBC Driver(ANSI); при другом имени впишите его в поле ODBC Driver.
  • Если драйвера нет — установите psqlodbc_x64.msi из папки C:\Program Files\Pulsonix Vault Admin 14.0 (с правами администратора).
  • Проверьте, что порт PostgreSQL (обычно 5432) открыт в брандмауэре сервера и рабочего места.
  • При ошибке драйвера Pulsonix сам пытается найти рабочий альтернативный драйвер и сообщает об этом.

14.9. Администрирование (для справки)

  • Пользователи и группы — вкладки Users и Groups диалога Vault Setup. Права назначаются группам (чтение/запись по типам элементов, удаление, просмотр журнала, изменение пользователей и т. д.). Группу и пользователя admin удалить нельзя. Право «Alter Users and Groups» позволяет сбросить чужой пароль — давайте его только администраторам. Пароли хранятся в виде хеша и не восстанавливаются, только сбрасываются.
  • Revision Naming — схемы имён ревизий: до трёх уровней, числа или буквы, префикс, начало и шаг (например 1.0, 1.1, 2.0); отдельно для проектов и для библиотек.
  • Attributes — дополнительные поля таблиц Vault (например Mfr для Parts), заполняются из атрибутов при Check In и доступны в поиске.
  • Vault Admin (отдельная установка VaultAdminSetup) — вкладки Backup, Restore, Settings. Restore existing восстанавливает рабочее хранилище; Restore new Vault создаёт копию с новым Vault ID. Не разворачивайте Restore existing на втором сервере параллельно с рабочим — получатся два хранилища с одинаковым ID.
  • vadmin — консольный вариант для расписания резервных копий: действия backup, restore, clone, install, view, help.
  • Во время резервного копирования и восстановления Vault недоступен клиентам.
  • Обновление со старых версий: резервная копия → установка PostgreSQL 14.5 (порт увеличится, например 5432 → 5433) → создание базы → Restore existing → новый порт в Sign In → вкладка Versions → Update Database (нужно право Database Maintenance).

14.10. Vault и Database Connection (PDC)

В PDC есть тип подключения Vault (Database Connection Setup → Database Type): параметры берутся из Vault Setup автоматически, и становится доступен параметрический поиск по всем Parts в Vault. Insert Component и Change Part через такой PDC используют Part из Vault независимо от пути поиска библиотек.

18. Разбор вопросов из переписки: перенос OrCAD → Pulsonix, библиотеки, PCB

В этой главе собраны конкретные ситуации, вопросы и решения, разобранные в переписке по проекту переноса схемы F220 (папка Vavilov) из OrCAD 9 в Pulsonix 14 Corporate. В отличие от главы «Диагностика и типовые проблемы» общего руководства (глава 15), здесь — не общие рекомендации, а конкретные диалоги «вопрос → что проверяли → что сделали», которые могут повторяться в похожих проектах.

18.1. Подготовка в OrCAD перед переносом

Перед переносом схемы, сделанной в OrCAD 9, в Pulsonix имеет смысл сначала «долечить» её средствами самого OrCAD:

  • Прогнать Physical DRC в OrCAD Capture и разобрать ошибки по одной, а не все сразу — так проще понять причину каждой (пользовательский принцип «давай по одной ошибке убирать» оказался эффективным и для Pulsonix-части проекта).
  • Проверить аннотацию позиционных обозначений и отсутствие дублей.
  • Экспортировать схему в формат EDIF — это нейтральный формат, который Pulsonix умеет читать через File → Import Design Data (путь импорта EDIF в Pulsonix может отличаться по версиям — сверяйте по пункту Setup → Import / File → Import Design Data в Вашей установке).
  • Если после импорта EDIF часть компонентов осталась без привязанного Part — это нормально и исправляется на стороне Pulsonix через Library Manager (см. 18.3).
Важно

EDIF переносит геометрию символов и список соединений, но не гарантирует совпадения имён Part с библиотеками Pulsonix. Самая частая следующая проблема после импорта — отсутствие футпринта у Part (см. 18.2).

18.2. Translate To PCB: типичные ошибки и их устранение

После того как схема приведена в порядок и ERC не выдаёт ошибок, выполняется Tools → Translate To PCB (см. также п. 7.1 общего руководства). В реальном проекте типично появляется отчёт с ошибками по отдельным компонентам — ниже разобраны конкретные случаи.

«У компонента нет назначенного футпринта» (varistor, con2, C_3, C_1, B82721A_0 и т.п.)

  • Отчёт Translate To PCB перечисляет компоненты построчно: имя Part и чего ему не хватает (обычно — футпринта или совпадающего количества выводов).
  • Решение по каждому имени Part отдельно — через Library Manager найти этот Part, открыть его в редакторе Part (Parts Editor / Part Wizard) и привязать нужный футпринт (см. 18.3).
  • После правки библиотечной записи — не редактировать компонент на схеме «вручную», а выполнить Reload From Library, чтобы схема подтянула обновлённый Part (см. 18.4) — иначе на схеме останется ссылка на старую версию, и повторный Translate To PCB выдаст ту же ошибку.

«Design already has part… but with a different version…»

Это предупреждение означает, что в самом проекте (схеме) уже «запечён» снимок описания Part — он отличается от того, что сейчас лежит в библиотеке на диске (библиотека была отредактирована после того, как компонент разместили на схеме). Это штатная ситуация после правки Part в библиотеке. Решение: Utilities → Reload From Library по этому компоненту (или по всей схеме) с опцией Replace footprint with default, если нужно подтянуть именно новый футпринт (см. таблицу опций в 18.4).

«No pin name for terminal 3 of gate A» (при попытке сохранить Part)

Эта ошибка возникает в редакторе Part/Symbol, когда у вывода (терминала) вентиля не заполнено имя вывода (Pin Name) в таблице Gate Pins Details. Нужно открыть эту таблицу (Parts Editor → страница Gate Pins Details / Pin Mapping) и для указанного терминала заполнить:

  • Pin Name — имя вывода (например, «3» или буквенное обозначение по даташиту);
  • Pin Type — не должен оставаться <Undefined>; для пассивных компонентов (резисторы, конденсаторы, варисторы) обычно ставится Passive;
  • Logic Name, Pin Swap, Gate Swap Group — по необходимости, для логических компонентов.
Отдельный случай — задвоенный вентиль

Если в мастере Part Wizard на одной из страниц значение Gate Count показывает «2» вместо ожидаемой «1» — в описании Part случайно создан лишний (дублирующий) вентиль. Нужно вернуться на страницу «Schematic Symbols» мастера и удалить лишний вентиль до нажатия Finish; иначе сохранённый Part будет содержать два одинаковых вентиля и путать соответствие выводов.

18.3. Part Wizard и Library Manager: создание и правка Part

Модель данных Pulsonix разделяет Symbol (условное графическое обозначение на схеме), Footprint (посадочное место на плате) и Part — запись, которая связывает их вместе и описывает соответствие выводов (pin-to-pad). Отдельно от общего описания в п. 6.1–6.2 общего руководства — ниже конкретные практические шаги, проверенные в этом проекте.

Создание нового Part с несколькими вариантами футпринта

  • Library Manager → вкладка Parts → New Part (или Part Wizard, если нужен пошаговый диалог).
  • На странице мастера есть поле библиотеки (например, «lev» — своя рабочая библиотека вместо правки общей корпоративной) и список футпринтов «In Library» / «In Part» с кнопками Add >>, << Remove, Up, Down.
  • Чтобы у одного Part было несколько альтернативных футпринтов (например, разные корпуса одного номинала), нужно добавить их все в список «In Part» через Add >> — именно так, а не через отдельные Part на каждый корпус. Выбор конкретного футпринта из нескольких, прикреплённых к Part, делается уже на схеме в диалоге Properties компонента, в поле Footprint.
  • Если список «In Part» оставить пустым и попытаться сохранить Part для использования в PCB — Pulsonix переспросит «это компонент только для схемы (schematics only part)?» — соглашаться с этим стоит только для чисто документационных символов без платы.
  • На странице Gate Pins Details проверьте, что у каждого вывода заполнены Pin Name и Pin Type (см. 18.2); для нового Part именно здесь чаще всего остаются незаполненные ячейки.
  • Готовый Part сохраняется в библиотеку (Save To Library); после этого полезно выполнить Regenerate Part/Footprint Library Indexes (п. 6.2 общего руководства), чтобы он сразу находился в поиске.

Так в проекте была создана библиотечная запись Lev_capacitor — Part для конденсатора на основе модели, импортированной из файла .plx (VY1222M47Y5UQ6TV0, Vishay) — с привязанным футпринтом C3C6 и выводами Pin Type = Passive.

Поле Footprint в Part Details и кнопка «Choose»

На странице Part Details есть поле Footprint со списком уже прикреплённых к Part футпринтов и кнопкой выбора. Это поле — для футпринтов. Отдельное поле SCM Symbol показывает привязанный символ схемы; у записей типа PCB Only (Part создан «только для платы», без символа) это поле заблокировано и кнопка «Choose…» рядом с ним не работает — это нормальное поведение для такого типа записи, а не ошибка интерфейса. Если нужно отредактировать именно связь символа и Part, редактировать нужно не это заблокированное поле, а сам Part, у которого тип не «PCB Only».

Создание футпринтов под конкретные компоненты

В проекте были созданы, в частности: футпринт варистора B72207S0461K101 (по корпусу реального диска варистора) и стандартный футпринт 0805 для чип-компонентов — оба через Footprint Wizard/Footprint Editor, с проверкой по контрольному списку из п. 6.3 общего руководства (геометрия площадок, маркер первого вывода, courtyard, 3D-модель).

18.4. Диалог Reload From Library — опции по пунктам

Этот диалог (Utilities → Reload From Library) обновляет размещённые на схеме/плате компоненты в соответствии с текущим содержимым библиотеки. Он особенно важен сразу после правки Part — без него изменения в библиотеке не попадут в уже начатый проект.

ОпцияНазначение
Only reload if different versionПерезагружает только те компоненты, у которых версия в проекте отличается от версии в библиотеке — безопасный режим по умолчанию, не трогает то, что не менялось.
Keep attribute styles / positions / local valuesСохраняет то, как атрибуты (позиционное обозначение, номинал и т.д.) расположены и оформлены на конкретном экземпляре — перезагрузка обновит только структуру/данные Part, не «подвинув» надписи на листе.
Keep local functional logic names / local Spice attributesНе затирает локально заданные для конкретного экземпляра логические имена и SPICE-атрибуты значениями по умолчанию из библиотеки.
Replace footprint with defaultКлючевая опция, когда нужно принудительно подтянуть футпринт, который только что был изменён в библиотечном Part. Без этой галочки у компонента может остаться старый (локально переопределённый) футпринт, даже если Part в библиотеке теперь ссылается на другой.
Replace pin networksОбновляет привязку выводов к цепям по новому описанию Part — полезно, если в Part изменились имена/типы выводов.
Re-apply name stem from partВозвращает префикс позиционного обозначения (например, «R», «C») к значению, заданному в Part, если он был случайно изменён локально.
Match position of first padПри замене футпринта совмещает новый футпринт с экземпляром по позиции первой площадки, а не по центру — удобно, когда новый футпринт имеет другую привязку начала координат.
Replace gate symbols with defaultsОбновляет графику вентилей символа до версии из библиотеки.
Keep pin position/style overridesСохраняет локальные изменения расположения/оформления отдельных выводов на символе.
Update predefined netsОбновляет автоматически подключаемые скрытые цепи питания/земли по новому описанию Part.
Match pins by position / gates by pin namesПравила сопоставления старых и новых выводов/вентилей при структурных изменениях Part — по расположению или по именам.
Keep local pin typesНе затирает типы выводов, заданные локально на экземпляре, значениями по умолчанию из Part.
Reload nets assigned to ungated pinsКасается выводов, не привязанных к конкретному вентилю (ungated) — обновляет назначенные им цепи.
Reload Doc SymbolsОбновляет документационные символы (рамки, штампы и т.п.), если они тоже загружаются из библиотеки.

Практический сценарий: отредактировали Part в библиотеке (например, привязали другой футпринт) → на схеме/плате выделяете компонент(ы) → Utilities → Reload From Library → ставите галочку Replace footprint with default (плюс, при необходимости, Replace pin networks) → OK. После этого повторный Tools → Translate To PCB должен пройти без прежней ошибки по этому компоненту.

18.5. Диалог Change Part: подбор и замена Part

Диалог Change Part (контекстное меню компонента → Replace Part, либо Utilities → Replace Part) заменяет Part у уже размещённого компонента, не трогая его положение на схеме.

  • Поле Look In задаёт, где искать замену: конкретная библиотека, все подключённые библиотеки, или только текущий проект.
  • Флажки Same Footprint и Same Symbol сужают список до Part, совместимых по футпринту и/или по символу с тем, что заменяется — это основной способ подбора «похожего» Part без необходимости помнить его точное имя.
  • Если нужный Part (например, Lev_capacitor) не появляется в списке при включённых фильтрах Same Footprint/Same Symbol — значит, по этим критериям он не совпадает с текущим: например, у него другой набор футпринтов или другой символ. Решение — либо снять один из фильтров (Look In → All Libraries, без Same Footprint), либо убедиться, что искомый футпринт действительно прикреплён к Part «In Part» (см. 18.3), либо выполнить Regenerate Library Indexes, если Part был только что сохранён и индекс библиотеки ещё не обновился.
  • Строка результата вида «Matched: 0 of 1» означает, что после применения фильтров ни один Part не подошёл — это сигнал проверить сами фильтры, а не повторять поиск с тем же запросом.

18.6. Импорт библиотек .plx (SamacSys / Ultra Librarian / SnapEDA)

.plx — нейтральный формат обмена библиотечными данными («Pulsonix Library Transfer»), которым отдают готовые модели компонентов такие сервисы, как SamacSys, Ultra Librarian, SnapEDA.

Проверенный на практике способ

Файлы .plx надёжно импортируются именно через функцию импорта внутри Library Manager (Library Manager → Import), а не через прямое открытие файла командой File → Open — так получилось избежать ошибок разбора на нескольких моделях в этом проекте.

  • Типичная ошибка при импорте — «End of file reached whilst looking for 'netlist' section». В этом проекте она в двух отдельных случаях оказалась вызвана не несовместимостью формата, а тем, что сам файл .plx был скачан не полностью (обрезан) — ошибка возникала на разных строках файла (в одном случае около строки 100, в другом — около строки 336), что типично для обрыва закачки, а не для системной проблемы формата.
  • Проверка: откройте «плохой» .plx текстовым редактором и посмотрите, завершается ли он закрывающими скобками секции netlist/compDef; у корректного файла (например, рабочего VY1222M47Y5UQ6TV0 на ~105 строк) все секции — padStyleDef, textStyleDef, patternDef, symbolDef, compDef с attachedPattern — закрыты, и файл не обрывается на середине.
  • Если файл действительно обрезан — единственное решение — перекачать его заново с сайта-источника (SamacSys/Ultra Librarian/SnapEDA), а не пытаться «исправить» импорт.

18.7. Многостраничные схемы: Multi-Screen, печать/плоттер отдельных листов

  • Сообщение об ошибке вида «не готов принимать команды» в режиме Multi-Screen означает, что схема и плата открыты как отдельные синхронизированные окна, и в одном из них в этот момент открыт модальный диалог — нужно его закрыть, прежде чем продолжать работу в другом окне. Режим Multi-Screen переключается в настройках интерфейса (Tools → Customise / Options, вкладки, связанные с режимом отображения окон) — сверяйте точный пункт по Вашей версии, так как он не выводится отдельной командой в основном меню.
  • Если компонент или часть схемы «улетели» за пределы видимой области листа — используйте View → World View (W), чтобы увидеть всю схему целиком и найти потерянный объект, либо команду подгонки масштаба под весь лист/выделение (обычно — «Zoom to Fit» / «a» в некоторых конфигурациях, сверяйте по строке состояния).
  • Если рамка листа «не двигается» при уменьшении масштаба — это обычно означает, что рамка — часть профиля листа (Drawing Profile) и закреплена операцией Lock, либо находится на слое, который не выбран для редактирования; проверьте Lock/Unlock (Utilities) и активный слой/группу объектов.
  • При печати многостраничной схемы, если часть листов выводится с сообщением вида «страница … не распечатана» — проверьте, что каждый лист действительно включён в список для печати/плота: печать и вывод в производственные форматы в Pulsonix настраиваются в первую очередь через CAM/Plot (Shift+P) (с явным списком страниц/слоёв в наборе плотов), а не только через File → Print — обычный Print печатает активный документ «как есть» и может не включать все листы многостраничного проекта без явной настройки диапазона страниц.

После Translate To PCB непривязанные компоненты лежат в Component Bin (клавиша «B»). Их перетаскивают на плату по одному, либо используют Tools → Place Around Board, чтобы расставить все сразу вокруг контура платы, а затем вручную разложить по месту (см. также п. 8.3 общего руководства).

  • С нуля: Insert → Board — нарисовать контур вручную (прямоугольник/многоугольник) либо загрузить готовый профиль платы (Load PCB Profile), либо импортировать контур из DXF/IDF/STEP (см. п. 8.2 общего руководства).
  • Из другого проекта: откройте тот, другой, проект платы отдельным окном, выделите в нём контур (и, при необходимости, крепёжные отверстия/запретные зоны), скопируйте (Ctrl+C), переключитесь в окно текущей платы и вставьте (Ctrl+V). Размерные линии

Не подтверждено окончательно

Перенос отдельных элементов (не всей платы) из другого проекта

Предупреждение о версии библиотеки

При таком переносе компонентов между проектами Pulsonix может показать предупреждение о том, что у перенесённого компонента Part «другой версии», чем в текущем проекте/библиотеке (та же природа, что и ошибка из п. 18.2 «different version»). Исправляется так же — Reload From Library по перенесённым компонентам.

18.11. Кейс: идентификация LED-индикатора и подбор аналогов (BD-F304RD)

В проекте потребовалось подобрать библиотечную модель для установленного семисегментного двухразрядного индикатора, маркировка которого не находилась напрямую в доступных библиотеках.

  • Физически установленный индикатор: BD-F304RD (Bright LED Electronics) — двухразрядный семисегментный индикатор формата 0,3″ (7,62 мм), с общим катодом (common cathode), сдвоенное управление (duplex drive). Подтверждено по технической документации: 10-выводная распиновка (1=Cathode G, 2=Cathode DP, 3=Cathode A, 4=Cathode F, 5=Common Cathode D2, 6=Cathode D, 7=Cathode E, 8=Cathode C, 9=Cathode B, 10=Common Cathode D1), корпус 15,0×15,5×7,2 мм.
  • Похожие по маркировке, но НЕ подходящие по схеме индикаторы: Everlight ELD-316SURWA/S530-A3 — подтверждено визуально по PDF-документации, что это индикатор с общим анодом (common anode), то есть электрически несовместим с BD-F304RD при одинаковой букво-пиновой раскладке. Everlight ELD-305SURWA/S530-A3 (тот же суффикс «SURWA») — предположительно также общий анод (по семейству суффикса), но это не подтверждено визуально отдельно, в отличие от 316-й модели — если встретите этот индикатор, сверяйте полярность по собственному PDF, а не по аналогии.
  • Подтверждённые аналоги (drop-in) для BD-F304RD — совпадают по механике 15,00×15,50×7,20 мм, общий катод, 10 выводов (DIP): Lumex LDD-F304NI (актуальная позиция производителя) и Kingbright DC03-11SRWA (статус Obsolete — снята с производства, подходит как замена только из остатков складских запасов, для новых закупок использовать Lumex).
Вывод для похожих случаев

Похожий корпус и похожая маркировка (например, общий суффикс серии) не гарантируют электрическую совместимость — полярность (общий катод/общий анод) нужно сверять по даташиту каждой конкретной позиции отдельно, а не переносить с «похожей» модели той же серии.
